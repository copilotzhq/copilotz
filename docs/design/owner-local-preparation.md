# Private local named preparation and View flow

## Scope and simplification

Fresh same-owner local Actions and Processors can prepare an ordinary Collection
record through a registered text View and execute the captured child either
locally or on a worker. This remains an internal placement capability; it adds
no public placement option or retained-local-history restart contract.

The former direct-only local child adapter now returns both bound call methods
from one existing child port. Direct and named calls share the same wait limit,
raw-call tracker, cancellation and result projection. Two adapter instances
would incorrectly double that budget. Both local drivers capture the optional
named method once. The Processor driver consolidates its direct/named
current-check and uncertain-outcome handling into one small private function.

Parent decoding uses the existing closed worker/local selector. The logical
preparation key and intent still exclude placement, attempt and current source
or renderer values. A local Processor retry can reuse its already-captured child
without a second render, mapper call, child execution or capture.

No renderer, capture table, waiter, policy bundle, transport route or execution
lease is added. The production-file delta for this slice is 137 added / 116
removed lines (net 21), including comments; that is a source measurement, not an
executable-complexity measure.

## Authority and genuine local start

The shared prepared-command proof applies to both parent placements. Original
source/reference/resource permission is required on capture, duplicate reuse,
claim/input, mutation and result access. Current visibility does not replace
permission for the original captured projection.

Before a local child's assignment is activated, execution authenticates the
exact pending private start and passes the genuine owner-control caller to the
original-source policy. That policy must permit its intended claim-time context.
No worker identity or active local assignment is fabricated, and the private
start marker alone grants nothing. Later checks use the actual live caller. The
shared child policy remains mandatory; omission still refuses admission.

Known post-COMMIT private loss suppresses the caller's result without erasing
committed capture. Unknown admission stops the owner and retains parent
occupancy; neither a caught exception nor raw drain authorizes reexecution. A
held database transaction acknowledgement blocks the owner command pump.
Independent SQL observations during that hold are not concurrent owner commands.

## Validation

Independent broad runtime gates passed 421 cases under actual PostgreSQL
configuration (preparation 87, core 114, canonical 220 across all 17 files), 95
pure port/driver cases and 12 role-bundle cases. All used normal typechecking
with zero failed/skipped runtime cases. The 408 unique disposable databases were
created/dropped once, no sessions remained and PostgreSQL was stopped.

That candidate's static pass found an unused type import and a test callback
that could use const. Those two lint-only corrections have a separately frozen
review and targeted rerun; the original static failures remain in the evidence.
The final correction independently passes the two actual PostgreSQL replay-close
cases, all 95 pure cases, role-bundle 12, lint/format and all six architecture
and package checks. The strict surface remains 46 exports / 16 external imports
/ 725 production modules. All 1,601 final source hashes and sibling hashes
match; the two additional databases were dropped and PostgreSQL stopped.

This is split correction evidence, not a claim that the broad gates were rerun
unchanged on the later lint-only snapshot. No checker or runtime assertion was
weakened.

The actual matrix covers both transports, local Action/Processor parents,
local/worker children, changed source/renderer values and Processor retries.
Additional actual-host cases cover original-reference denial at claim/input,
result and duplicate; closing the owner on the framework's prepared replay
receipt read; committed/aborted uncertain admission; and close while a committed
preparation acknowledgement is held. The shared adapter fault suite retains its
original direct cases and runs their named counterparts through the real raw
tracker. Driver tests verify callback identity is captured before execution.

Earlier root failures remain recorded: the abstract Processor fixture context
needed an explicit typed runtime caller, and the first actual fixtures omitted
the required child policy. The diagnostic reproduced that refusal; explicit
fixture policy and correct original-source caller contexts fixed the setup.
Production permission checks were not weakened to make those cases pass.

## Remaining boundaries

Protected/content/deferred preparation, Processor effects, full
body/current-copy catalog semantics, general retained local/open-history
recovery, default model context migration and public mixed-placement
configuration remain separate gates. This is scoped parity, not a new full-suite
or release acceptance. No merge or package publication is included.
